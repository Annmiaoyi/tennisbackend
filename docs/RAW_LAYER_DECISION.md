# 原始波形采集 · 重要性论证与决策建议

> 回答一个问题：**要不要在 Watch 上采集并上传高频原始波形（L0 层）？**
>
> 结论：**要，但不是现在以产品默认开启的方式采。** 详见 §5 建议方案。
> 本文只做论证，不涉及实现。通道细节见 [WATCH_CHANNEL.md](WATCH_CHANNEL.md)。

---

## 1. 先明确「原始波形」指什么

| 项 | 内容 |
|---|---|
| 采集频率 | 加速度 800 Hz + 设备运动 200 Hz，按最近邻对齐到每条加速度样本 |
| 单条样本 | `t` + `ax,ay,az` + `rx,ry,rz` + `gx,gy,gz` + `qx,qy,qz,qw`（14 个字段） |
| 形如 | `{ "session": {…}, "samples": [ … ] }`（形如 `raw_package`） |
| 存放位置 | L0 原始层 `var/raw/acemate_raw.db` + `var/raw/files/*.json[.gz|.zz]` |
| 铁律 | **只 INSERT，永不 UPDATE / DELETE**（SQLite 触发器在库层面强制） |
| 幂等 | 同形态同字节重传 → `duplicate`；不同字节 → `revision+1`，历史版本永久保留 |

> ⚠️ 这与**会话结论**（`MatchSession`，几十 KB）是**两个不同层级的东西**。
> 会话结论是所有产品功能的来源；原始波形是**研发资产**。不要混为一谈。

---

## 2. 为什么它重要（5 条）

### 2.1 它是采集的「一次性事件」，丢了就永久没了

球打完那一刻的物理信号只存在一次。结构化结果（`training_sessions` + `stroke_records`）
是**可重算的** —— 只要有原始波形，删掉重跑就能得到新版结果。
反过来不成立：原始波形丢了，任何算法都再也无法恢复那一刻。

> 这是**不可逆性**，不是"要不要省点空间"的问题。

### 2.2 没有它，识别算法永远无法迭代

当前 Watch 的分类是**启发式阈值状态机**（只看峰值角速度、重力方向符号），
能可靠区分的只有正手 / 反手，发球靠"手臂高举"粗判。目标是
**38 维特征 + CoreML 分类 + HMM 平滑**。而 38 维特征**全部来自原始波形**。

没有原始数据，以下三件事一件都做不了：

| 要做的事 | 为什么必须原始波形 |
|---|---|
| 训练模型 | 特征是从波形算出来的；没有波形就没有训练集 |
| 评估新算法 | 需要把新旧算法**回放同一批波形**做对比 |
| 回归验证 | 改了阈值/模型后，要能在历史数据上复现"改好了还是改坏了" |

### 2.3 标注链路（L1）完全依赖它

L1 标注层的存在意义就是产出**逐拍真值**：人工对着波形 + 视频，
标出每个 `impactTime` 的真实击球类型，再导出 38 维 CSV 训练模型。

```
原始波形 ──→ 标注工作台（波形 ↔ 视频逐拍对齐）──→ dataset.csv ──→ CoreML 模型
   ↑                                                                    │
   └──────────────── 模型回填 L2（长期目标）─────────────────────────────┘
```

**没有波形 = 没有标注 = 没有监督学习 = 永远停在启发式。**

### 2.4 「今天读不出」不等于「以后读不出」

落点、甜区、旋转、过网高度这些维度，手腕单点 IMU 现在测不到，
所以后端字段保持 NULL。但如果将来引入视觉或拍柄传感器，
**历史原始数据仍然可以重新分析**。

一旦采用"解析不出来就不存"的策略，这些包就永久丢失了 —— 相当于用今天的算法水平
为明天封顶。这正是 L0 设计的初衷：**原始层可能比当前算法更"聪明"**。

### 2.5 它是质量问题的唯一定位手段

结构化结果只有聚合数字（比如 `stroke_count = 386`）。当数字异常时，
只有原始波形能回答"**为什么**异常"：

| 现象 | 只看结构化数据 | 有原始波形 |
|---|---|---|
| 配平门禁判 `suspect`（未识别拍 > 5%） | 只知道分类器可能失灵 | 能看出是分类器失灵，还是**手表中途松动/脱落** |
| 某场球速突然全为 NULL | 无法解释 | 能看出传感器权限被拒或采集中断 |
| 某学员数据明显偏低 | 无法解释 | 能看出是佩戴手腕配错（正反手整体互换） |

## 3. 代价（必须如实计算）

### 3.1 体积

按参照实现实测口径：**1 小时 ≈ 700 MB 未压缩，DEFLATE 压缩后 ≈ 70 MB**（约 10×）。

| 场景 | 压缩后体积 |
|---|---|
| 1 场（1 小时） | ≈ 70 MB |
| 1 周 3 场 | ≈ 210 MB |
| 1 年（150 场） | ≈ 10.5 GB |
| 1 年 × 100 名用户 | ≈ **1 TB** |

> 单机 SQLite + 本地磁盘在**开发者自采 + 小范围受试者**规模下完全够用；
> 但**面向全量用户默认开启是不可行的**。

### 3.2 功耗（**最硬的约束**）

800 Hz 连续采样意味着传感器几乎满负荷工作。在 Apple Watch 上，
一场 1 小时的高频采样会显著加速掉电 —— 而用户打开 App 是为了打球，
不是为开发者采数据集。

**这条决定了：产品路径上不能默认开启。** 用户不会接受"为了给算法团队供数据"
而牺牲一半续航。

### 3.3 传输与存储链路更长

70 MB 要走 `WCSession.transferFile` → iPhone 落盘 → HTTP 上行。
虽然 WCSession 有后台队列保证送达，但链路越长失败点越多
（参照实现就踩过"文件回调绕主线程 → 大文件被系统清理"）。

### 3.4 设备兼容性收窄

`CMBatchedSensorManager`（800 Hz 的前提）要求 **Apple Watch Series 8 / Ultra + watchOS 10+**。
开启原始采集等于把可用用户砍到一部分机型。

### 3.5 隐私与合规

高频运动信号含**个人生物特征**（步态可识别到个人）。需要：
明确授权、加密存储、定义留存期与脱敏策略。
这一点在"只存聚合结果"时几乎不存在。

## 4. 一张决策表

| 如果目标是…… | 需要原始波形吗 | 说明 |
|---|---|---|
| 让用户看到训练时长 / 拍数 / 心率 / 卡路里 | ❌ 不需要 | 会话结论足够，几十 KB |
| 跨学员排行榜、纵向趋势 | ❌ 不需要 | 走 L2 聚合 |
| **把正反手之外的 4 类分准** | ✅ **必须** | 启发式上不去，必须上模型 |
| **区分截击 / 切削 / 高压** | ✅ **必须** | 仅靠聚合数字无从下手 |
| 定位"这场数据为什么异常" | ✅ 强烈建议 | 见 §2.5 |
| 未来做落点 / 甜区 / 旋转分析 | ✅ 建议先存 | 存下来才有未来（§2.4） |

---

## 5. 建议方案：**分阶段，不默认开启**

### 阶段 A —— 现在（产品可用性优先）

- 产品路径上**默认关闭**原始采集
- 保留一个显式的「开发者 / 数据贡献」开关，**必须同时告知体积与耗电**
- 这一阶段的首要任务是把**会话结论通道**打通并保证字段正确
  （见 [CONTRACT.md](CONTRACT.md) §3.3）——**没有它，采再多原始数据用户也看不到东西**

### 阶段 B —— 模型训练期（**必须做，绕不过去**）

- 招 5~10 名受试者，每人 3~5 场，在**可控条件**下开启原始采集
- 目标：攒够标注样本，训练第一版 CoreML 分类器
- 这一步不做，分类就永远停在"只能分正反手"

### 阶段 C —— 上线后

- 默认关闭；提供"贡献数据解锁高级分析"之类的**等价交换**选项
- 同时定义留存期（例如受试者数据 12 个月后归档 / 删除）

### 5.1 值得评估的中间方案：降频采样

800 Hz 不是唯一选择。挥拍检测与分类的**主导信号**（手臂旋转、引拍-击球-随挥）
集中在低频段；800 Hz 主要多覆盖了击球瞬间的**拍面高频振动**。

| 方案 | 每小时（压缩后） | 保留的信息 |
|---|---|---|
| 800 Hz 加速度 + 200 Hz 设备运动 | ≈ 70 MB | 完整（含拍面振动） |
| **200 Hz 设备运动**（现有能力，只加落盘） | **≈ 8 MB** | 旋转 / 姿态 / 挥拍节奏，**丢失击球瞬态** |
| 混合：常态 200 Hz + 检测到击球窗口时升到 800 Hz | ≈ 15 MB | 兼顾（实现复杂度最高） |

> 建议在阶段 B 用**同一个受试者、同一批动作**，同时采 800 Hz 与 200 Hz 两版，
> 对比分类精度差多少 —— **用数据决定要不要付 9 倍体积的代价**。
> 这类 A/B 只能做一次（动作不会完全复现），值得排进阶段 B。

---

## 6. 决策要点（一句话版）

1. **原始波形必须要有** —— 它是唯一不可再生、且算法迭代唯一依赖的东西。
2. **但绝不能产品默认开启** —— 功耗与体积决定了这一点。
3. **优先级排在最前面的仍然是会话结论通道** —— 它决定用户能不能看到东西，
   原始波形决定**东西准不准**。两者都重要，但不能本末倒置。
4. **先做小样本、可控条件的采集**，把算法从"只能分正反手"推到可用水平，
   再谈全量留存。
